## 先说清楚：缓存是整个 App 共用的

元宝的 WebView2 缓存不按对话分目录，一个账号下所有对话的图片都存在同一个 `Cache_Data` 里。所以直接捞会捞出一堆别的东西：

国徽、西北大学校徽、南开校徽、中央纪委网站截图、Haier、GitHub、bilibili、酷我音乐、钢琴键盘、基金走势图、柱状图、大脑解剖图、卡车照片、2048 游戏图标、别的游戏截图……

**处理方式：第 1 轮挑出的 68 张挪进 `其他对话/`，编号保持不变，清单里 `归属` 标为「其他对话」，图廊页尾独立分区默认展开。** 没有删 —— 要「全部记录」就都留着，只是不混在一起。第 2 轮经核对没有新的混入项。

判定标准只有一条：**画面主体是不是这只戴圆眼镜的猫**。是部件（眼镜、猫耳、尾巴、假发、外套）、白模、绿幕帧、设定卡、它出现在自己项目页面里的截图，都算；不是就不算。

## 为什么要抢救

这个项目在元宝里谈了几十轮，**很多图看着有，但一次都没点过下载**。元宝没有「导出全部图片」的入口，对话一多，这些图就只剩客户端缓存这一份残骸。

而缓存会被清理、会被新内容挤掉、会在重装客户端时归零 —— 第 2 轮就实地验证了这一点：第一轮的 526 条图片记录在几小时后已被新对话换批成 254 条。

所以做了这次抢救：把 App 缓存里的图片按字节全量提出来，去重、分组、编号、建清单。

## 恢复了什么、没恢复什么

**恢复了**：图片本体，逐字节原样，带 sha1。

**没恢复**：对话正文。这一条要说清楚，不是没试：

- 元宝是 WebView2 套壳，数据在 `%LOCALAPPDATA%\com.tencent.yuanbao\EBWebView`
- `Local Storage` / `Session Storage` / `IndexedDB` 里搜「哈士喵 / 眼镜猫 / 八向 / 白模 / 绿幕 / status-candidate」，**命中 0**
- 缓存里命中关键词的 48 个条目，解开 gzip 后逐个看，都是项目自己的 HTML 文档（如 8 向导演台），**不是聊天记录**
- 原因：对话是流式响应，不落磁盘缓存；正文只在服务端

**要做全量正文，只能从元宝界面里手动导出/分享**，本地做不到。

## 怎么恢复的

```
第 1 轮
EBWebView\Default\Cache\Cache_Data     638 个条目
   ↓  读前 16 字节判 magic（PNG/JPG/GIF/WEBP）
526 张图片 → sha1 去重 → 304 张唯一图
   ↓  按尺寸 + 绿占比分 4 组，逐张目视通读
236 张本项目素材（+ 10 桌面散件 = 246）+ 68 张其他对话

第 2 轮
缓存换批后 254 条图片记录 → magic 识别 → 173 张唯一图
   ↓  与档案现有 356→314 张做 sha1 差集
42 张真新增（131 张重复）
   ↓  逐格目视核对（全览_1 / 全览_2）
37 张角色设定 + 5 张界面记录 → 全部并入
```

绿占比的算法：缩到 64×64，统计 `G > R+30 且 G > B+30` 的像素比例。> 0.35 判为绿幕类 —— 这个阈值能把绿幕拼板和普通成图干净分开。

重建 / 增量命令：

| 脚本 | 用途 |
|---|---|
| `_build/build.py` | 首轮全量构建（输入 `_yb_stage/`，已按约定删除，仅供追溯） |
| `_build/merge_round2.py` | 第 2 轮增量合并：读 `_fresh.json` → 分拣 → 缩略图 / 总览 → 追加清单 → 重建图廊。带 `--dry-run` |
| `_build/gallery.py` | **清单驱动**的图廊生成器，只读 `清单/图片清单.json`，改完清单重跑即可，不再依赖 stage |

通用版工具（含缓存提取、分拣、批量推送）见 [`yuanbao-asset-rescue`](https://github.com/604665656/yuanbao-asset-rescue)。

## 清单字段

`清单/图片清单.csv`（UTF-8 BOM，Excel 直接开）与 `清单/图片清单.json`，共 356 条：

| 字段 | 说明 |
|---|---|
| `组` | 所属分组；第 2 轮的组带 `本轮新增/` 前缀 |
| `文件` | 归档后的文件名；首轮 `序号_原缓存ID.扩展名`，第 2 轮 `R2_序号_原缓存ID.扩展名` |
| `原缓存ID` | 元宝缓存里的文件名，如 `f_000378`、`f_000605`，便于回溯 |
| `宽` `高` `模式` | 像素尺寸与色彩模式 |
| `字节` | 文件大小 |
| `绿占比` | 0~1，>0.35 即绿幕类 |
| `sha1` | 内容指纹，跨轮次 / 跨仓库查重靠它 |
| `完整性` | `完整` / `截断(缺N字节)` / `非图片` |
| `来源` | `元宝 App 缓存` / `元宝 App 缓存（第2轮）` / `桌面` |
| `归属` | `本项目` / `其他对话`。只筛本项目时按这一列过滤 |
| `轮次` | `第1轮` / `第2轮·13卷八向新文件` |
| `路径` | 相对本仓库根目录的原图路径，图廊直接读这一列，不再硬编码目录规则 |

## 已知问题

- **7 张缓存记录尾部被截断**，缺 13~54 字节。画面完整，Pillow 加 `LOAD_TRUNCATED_IMAGES` 可正常读；清单里标了 `截断`。
- **222 张重复图被丢弃**（第 1 轮，同一张图在缓存里存了多份）；第 2 轮另有 81 张缓存内重复 + 131 张与首轮重复，同样没有入库。
- **文件名不含语义**。缓存里没有原始提示词，所以只能按尺寸/绿占比分组、按序编号，做不到「这是猫耳」这种命名。语义靠 `总览/` 的大图人工认。
- 图上有「元宝 AI生成」水印的，是元宝自己加的，没有去除。
- **13 卷总包（5145 文件 / 2.1 GB）本地未下载**，若要完整纳入需先在元宝里下载那 13 个 zip 并给出本地路径。
